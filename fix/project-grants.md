## Findings / root causes
- `/pages/project-grants/index.vue:8-10` is only a thin route wrapper around the shared `<MapView2D default-dataset="project-grants" />`; the marker bug is not page-specific.
- **Primary marker-color bug:** `/lib/colors.ts:getProjectColorByBeneficiaries()` returns CSS custom-property strings (`var(--info)`, `var(--success)`, `var(--warning)`, `var(--danger)`, `var(--purple)`). The active MapLibre path `/composables/useMapMarker.ts:658-679` (`toProjectGeoJSON`) puts those strings into GeoJSON `properties.color`, then `/composables/useMapMarker.ts:386-401` (`addPointLayers`) feeds them to `circle-color: ['get','color']`. MapLibre style expressions require map-parseable colors; CSS `var(...)` is not a safe MapLibre color value, so the colored glow/center can fail or fall back, leaving the marker visually black. `/composables/useGeoJSONMarkers.ts:94-123` contains a duplicate project converter with the same unsafe color contract (not the current active path, but a future/regression risk).
- **Secondary visual cause:** the shared point stack intentionally paints the main circle almost opaque dark (`rgba(5,12,20,.96)`, `useMapMarker.ts:393-397`) and only adds a small colored center (`:398-401`). At world/low zoom, the dark base dominates even when the color parses correctly. This is a shared all-map styling function, so changing it globally must preserve species/crew contrast.
- Project cluster layers already use literal hex palettes (`useMapMarker.ts:56-63,268-284`), so the problem is the unclustered project-point layer, not the cluster palette.
- **Expanded card contrast bug:** `/components/map/ProjectPopup.vue:153-160` and `:216-220` use `var(--bg-tertiary)` as foreground text. In light mode this is `#fff` on the light `--bg-secondary`; in dark mode it is `#1a1a1a` on `#111`, making title/stat values nearly invisible. These should use `--text-primary`/`--card-foreground` (or a dedicated card text token).
- **Shared compact card is dark-only:** `/assets/css/main.css:1357-1384,1763-1776` makes `.pc` use root-only `--obs-panel-bg: rgba(0,0,0,.75)` and white-alpha text. There is no light-theme variant, so every map’s compact popup is a dark glass card even in light mode. The stylesheet is global (`nuxt.config.ts:98`) and the same preview system is wired by `useMapBase` for projects, species, and crews.
- Compact popup flow: `useMapMarker.ts:546-551` (`dispatchProject`) calls `openProjectPreview`; `/composables/useMapPopup/previewCard.ts:59-70,102-158` creates raw MapLibre HTML with `closeButton:false`, `closeOnClick:true`, `closeOnMove:true`; `/lib/map-utils.ts:330-375` (`buildProjectPreviewHTML`) renders the card. There is no visible close button; dismissal is implicit map click/move. The card body is made clickable by an imperative listener, but only the CTA is a keyboard-native control.
- `/lib/map-utils.ts:330-375` uses long single-line title styling (`main.css:1473-1481`, `white-space:nowrap; text-overflow:ellipsis`) and only shows location plus direct/indirect/total beneficiaries. `/lib/types.ts:7-14` confirms `ProjectData` has only title, location, coordinates, and beneficiary counts; funder/amount/category are not available despite the `ProjectPopup.vue` header comment claiming them. Do not design around unavailable grant metadata without extending/normalizing the data source.
- The full card is hosted by shared overlays in `/components/MapView2D.vue:117-123` and identically in `MapView3D.vue`; shared host CSS is `/assets/css/main.css:1581-1660`. `ProjectPopup.vue` also hardcodes English “Open in Google Maps”; compact labels “Project/Direct/Indirect” are likewise not fully localized.

## Exact change targets
1. `/lib/colors.ts:getProjectColorByBeneficiaries` plus both converters (`useMapMarker.ts:toProjectGeoJSON`; `useGeoJSONMarkers.ts:projectsToGeoJSON`): return literal hex/RGB map colors, or add a dedicated `getProjectMapColor...` and keep CSS tokens only for DOM styling. Never pass `var(...)` into MapLibre paint expressions.
2. `/composables/useMapMarker.ts:addPointLayers` (prefer a project-specific variant or dataset options): reduce the opaque dark base, increase colored fill/center, or use colored fill with a dark stroke. Keep the intentional dark treatment for other datasets only after visual regression checks.
3. `/components/map/ProjectPopup.vue`: replace background tokens used as text, add semantic heading/labeling, and localize the Google Maps action.
4. `/lib/map-utils.ts:buildProjectPreviewHTML`, `/composables/useMapPopup/previewCard.ts:createPopup`, and `/assets/css/main.css:.pc/.preview-card-popup`: redesign the shared compact card and its dismissal/focus behavior. Because this is shared, validate project/species/crew cards together.
5. `/components/MapView2D.vue` and `MapView3D.vue` shared overlay hosts plus `/assets/css/main.css` overlay rules: use one responsive detail-card shell (desktop centered dialog; mobile bottom sheet), semantic light/dark tokens, and consistent close/focus behavior. The route page itself needs no rendering change beyond regression coverage.

## Practical modern detail-card redesign
- Normalize each marker into a shared detail-card view model: type, accent (map-safe literal), title, location, primary metric, secondary metrics, optional image/metadata, and actions. Keep compact preview to title/location/total beneficiaries with a clear “View details” CTA; allow a two-line title clamp rather than ellipsis at one line.
- Use one visual language across project/species/crew: semantic `--map-card-bg`, `--map-card-fg`, `--map-card-muted`, `--map-card-border`, and accent tokens with explicit light/dark definitions; 12–16px radius, visible border/shadow, 44px minimum controls, `:focus-visible`, and a correctly colored MapLibre tip for all anchors.
- Give the on-map preview an explicit close button, accessible name, and Escape support; preserve click-away/move dismissal. Make the entire card keyboard navigable without attaching click behavior to a non-interactive `div`.
- Expand to a responsive dialog/bottom sheet with `aria-labelledby`, stable focus return to the marker/search origin, scrollable content, and a single primary action. Show only fields actually present; add funder/amount/category only after extending `ProjectData` and the loader.

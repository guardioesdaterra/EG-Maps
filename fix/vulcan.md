## Vulcan Observatory audit (read-only)

No files were edited; `git status` remained clean.

### Concrete root causes

1. **Phase filter excludes valid regional claims while reporting “all claims.”** `public/data/rare-earth/pococaldas/points.geojson` has 284 claims with phases `CONCESSÃO DE LAVRA` (48) and `REQUERIMENTO DE LAVRA` (4), but the UI defaults to canonical keys `CONCESSÃO`/`LAVRA` and has no `REQUERIMENTO DE LAVRA` key. `composables/useObservatoryControls.ts:137-145,436-458` performs exact `d.f` matching, so the default result is 232 rather than 284; `activeFilterCount`/summary still says no phase filter. Align `lib/map-utils.ts:537-543`, `useObservatoryControls.ts`, and/or normalize `useRareEarthData.ts:66-85` to one phase vocabulary. **Validate:** clean regional load should show 284; each phase chip should produce the expected subset.

2. **Year slider changes never re-run claim filtering.** `pages/vulcan-observatory/index.vue:354-360` mutates `yearMin/yearMax` directly. `useObservatoryControls.ts:419-423` watches those refs only for hash updates; only phase/category toggles call `debouncedFilter()`. Add filter invalidation in the controls watcher or page handlers. **Validate:** dragging either thumb, Play, and Reset must update `filteredPoints`, `ree-points`, the displayed count, and zero-result states.

3. **The page overwrites the filtered count after loading.** `composables/useVulcanObservatoryPage.ts:237-241` sets `filteredCount.value = allFeatures.value.length` after `loadRareEarthData()` even though the points watcher may already have applied filters. This can make stats disagree with `filteredPoints`/YearSlider. Remove the overwrite or call the canonical filter routine after restoration/load. **Validate:** header, slider count, data table, and rendered point count agree after initial load and every filter.

4. **Curated cultural entities are dropped whenever agent data loads.** `useVulcanObservatoryPage.ts:55-65` keeps only curated features whose properties contain `source`; all 124 features in `public/data/rare-earth/pococaldas/cultural-features.geojson` have no `source`/`source_id`, so they disappear once `culturalAgentsCombined` has features. Normalize curated records with a source (or retain source-less records) before merging. **Validate:** regional cultural data must include the 124 curated entities plus the deduplicated static/community entities, not just the 2,016 static-agent records.

5. **Cultural controls do not cover the actual entity schema.** `components/observatory/ObservatorySidebar.vue:245-256,329-363` exposes only four subtypes (`cultural_center`, `artist_group`, `indigenous`, `rural`), while the regional data also contains `marginalized` and `event`; source counts ignore source-less curated entities, and those records bypass source filtering because `src` is not in `sourceFilter`. Expand/normalize the metadata and make counts/filters operate on the same merged schema. **Validate:** source counts sum to total, and every subtype present in the data is filterable.

6. **Cultural map rendering is off by default while the cultural browser is visible.** `useObservatoryControls.ts:161-182` initializes `layerVis.cultural = false`; the sidebar is mounted at `pages/vulcan-observatory/index.vue:336-345`, but the map layer visibility sync in `useRareEarthLayers.ts:636-638` hides all cultural layers. Decide whether culture-first means default-on and align the initial state/UI. **Validate:** initial page behavior and the sidebar toggle must agree with the visible map.

7. **Polygon layers ignore claim filters.** `pages/vulcan-observatory/index.vue:80-82` passes raw `polygonsData`; `useRareEarthController.ts:186-199` adds them once, and `useRareEarthLayers.ts:569-577` loads the complete polygon collection. Year/phase/category filtering only updates points (`useObservatoryControls.ts:446-471`), while polygon visibility is only a boolean toggle (`useRareEarthLayers.ts:619-620`). Either derive filtered polygons using the same canonical criteria or explicitly separate/document polygon semantics. **Validate:** filter a single phase/year/category and confirm polygons do not show unrelated claims.

8. **Full-Brazil expansion leaves stale regional ancillary layers and requests missing assets.** `useRareEarthData.ts:165-171` changes to `all`; `load()` requests root `waterbodies.geojson` and `cultural-features.geojson` at `:153-158`, but those root files are absent. `loadResource()` (`:90-103`) does not clear prior values on failure, so regional water/cultural data can remain displayed while `isRegional` is false. Add root assets, clear/reconcile failed resources, or disable those layers on region switch. **Validate:** expand to Brazil while observing network requests and map sources; no Poços-only ancillary features may remain.

9. **Cultural data can be fetched twice.** `useCulturalAgentsData.ts:210-214` auto-loads on mount, while `useVulcanObservatoryPage.ts:237-240` explicitly calls `loadCulturalAgents()` in its page mount hook. `load()` has no in-flight guard. Remove one trigger or guard concurrent loads. **Validate:** browser Network should show one request per static cultural source per mount.

10. **Timeline/phase-panel architecture is split and stale.** Both pages wire the toolbar to `GeoPoliticalTimeline` (`pages/vulcan-observatory/index.vue:393`, `3d.vue:239`), which renders static `GEOPOLITICAL_TIMELINE`/`MINING_PHASE_TIMELINE` content; `components/observatory/tabs/TimelineTab.vue` and `components/ObservatoryTabPanels.vue` are not mounted by these pages. The active modal is not connected to `allFeatures`, year filters, or selected phases. Keep it intentionally static and label it as such, or replace it with the data-backed panel. **Validate:** opening Timeline must either remain clearly static or reflect the loaded region/filter state; do not validate the orphaned `TimelineTab` as the live UI.

### Title/typo references

No obvious misspelling of “Observatory” was found. There is a naming inconsistency that should be standardized: canonical page titles are `Vulcan Community Observatory...` in `pages/vulcan-observatory/index.vue:445-452` and `3d.vue:290-297`, while legacy UI/loading/export/footer strings use `Observatory of Vulcan` in `locales/en.json:7,28,641-642`, `components/MapView2D.vue:23`, `components/MapView3D.vue:20`, `composables/useDataDownload.ts:128`, and `components/GeoPoliticalTimeline.vue:190`. **Validate:** browser `document.title`, H1, loading overlay, download report title, and timeline footer should use the chosen canonical name in English and translated locales.
